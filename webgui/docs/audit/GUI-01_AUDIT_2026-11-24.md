## Corrections and evidence

The first screenshot showed two minor layout issues: the initial window covered desktop icon labels and the System Status report required scrolling. The initial rectangle was moved right and enlarged, and new windows cascade outside the icon columns when viewport bounds allow. A browser regression test checks the initial icon area and full report at 1280×800, opens Start and verifies two windows can coexist. Existing tests also cover keyboard/pointer actions, restore, persistence, small viewport, adapter isolation and unavailable real mode.

## Remaining limitations

Only the shell and read-only demo interface are accepted. Operational app windows are placeholders; real transport, auth, startup animation, actual telemetry, kiosk and hardware acceptance are later packages. Full visual approval on the actual VENTUNO display is not yet performed. The chosen default mode is demo for this isolated package, not an accepted production deployment default. Dependency audit is point-in-time; the package currently uses ESLint 9, which has a support/deprecation warning, to be reviewed separately. Font attribution is bundled with the third-party notices. No services on VENTUNO were changed.

Build smoke was run against the actual dist assets on a temporary loopback HTTP server with Chromium in a fresh page per mode. The server was closed after the check. The source tree was also checked for direct fetch/WebSocket/XMLHttpRequest/serial/USB/ROS client calls; none were found.
