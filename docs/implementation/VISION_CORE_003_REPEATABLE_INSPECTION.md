## Offline implementation notes

`repeatability.py` produces an ECU-local specification and yaw-transformed scene coordinates in millimetres. It checks the six approved profiles, their identifiers, schemas, revisions, capabilities and calibration dependencies against the current context and a fresh observation. The transform is not a MoveIt plan, IK result or collision check. Profile PCB rectangles describe required regions, not measured camera projections. `photography_views` adapts a verified plan to the existing photography contract; `complete_s05` binds its digest to workflow evidence. Existing generic workflow and photography APIs remain backwards compatible, so callers integrating this feature must use these adapters and the measured-coverage gate explicitly.

`SpatialCoverageEvidence` requires independently verified ECU-local footprints, capture view identities and a trusted provenance reference. Rectangle union/intersection is computed geometrically, including overlapping required regions; a caller supplies the explicit minimum. No image-derived metric estimates spatial coverage. A successful result can become a 0.2 `CoverageProof`; the caller remains responsible for verifying that the provenance and captured-view assertions originate from its trusted measurement and capture systems.

`RetryLedger` records only explicitly approved, independently verified QA decisions for blur, exposure or crop with valid measured coverage and a per-view bound. It never resumes a blocked workflow or dispatches motion or capture. After an actual interruption, reconcile external device state and use a new verified session before any further work; never replay side effects from the journal. Its SQLite transaction serializes competing decisions and request IDs are checked against journal events. The trusted caller supplies QA and approval references and verification assertions; this offline module cannot authenticate those external sources.

The canonical JSON manifest contains the plan and context, derived coordinates, measured footprint provenance, coverage result and retry records. Verify it against independently retained expected plan, evidence and decisions; a bare SHA-256 in the same document detects accidental changes but is not a signature and cannot authenticate a maliciously replaced document. Store real session artifacts and an independently protected digest privately when an operational archive exists. The synthetic tests contain no images or calibration data from a station. No live hardware integration or physical validation is claimed.

Optical orientation is explicit: each 0.3 ECU view requires a normalized XYZW quaternion in the ECU-local frame. The plan combines it with observed ECU yaw to derive a scene-frame quaternion, and passes the local orientation into the photography record. Legacy profiles may omit orientation, but cannot create a 0.3 plan until it is configured. No camera orientation is assumed. The record specifies the requested orientation; it does not prove the actual optical pose. Operational integration assumes an external trusted VGP adapter confirms the actual goal pose. Collision checking and IK are not implemented here. The retry ledger only records decisions and does not execute retries; a failure may require a new validated session after reconciliation.
